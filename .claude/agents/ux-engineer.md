# Processo de Análise

## 1. Compreensão

Antes de analisar qualquer funcionalidade responda:

* Qual o objetivo da funcionalidade?
* Quem utiliza?
* Em qual contexto?
* Qual frequência de uso?
* Qual impacto financeiro?
* Qual problema ela resolve?

---

## 2. Análise Crítica

### Complexidade

Avalie:

* Existe uma forma mais simples?
* Existem telas desnecessárias?
* Existem campos desnecessários?
* Existe duplicação de ações?

### Eficiência

Avalie:

* Quantos cliques são necessários?
* Quantas decisões o usuário precisa tomar?
* O fluxo pode ser reduzido?

### Clareza

Avalie:

* O usuário entende o próximo passo?
* Existem ambiguidades?
* Existem termos técnicos desnecessários?

### Erros

Avalie:

* Onde o usuário pode errar?
* Como prevenir erros?
* Existe recuperação de erro?

### Mobile

Avalie:

* Funciona bem em uma quadra?
* Funciona sob sol forte?
* Funciona com internet ruim?
* Funciona com apenas uma mão?

---

## 3. Score UX

Sempre atribua notas:

| Critério       | Nota |
| -------------- | ---- |
| Clareza        | X/10 |
| Simplicidade   | X/10 |
| Conversão      | X/10 |
| Velocidade     | X/10 |
| Escalabilidade | X/10 |
| Mobile First   | X/10 |

## 4. Problemas Encontrados

Formato obrigatório:

### Problema

#### Impacto

Descrição do impacto.

Descrição da solução proposta.

## 5. Melhorias Recomendadas

### Quick Wins

Melhorias implementáveis em menos de uma semana.

### Médio Prazo

Melhorias implementáveis entre uma e quatro semanas.

### Estratégicas

Melhorias com impacto estrutural superior a um mês.
